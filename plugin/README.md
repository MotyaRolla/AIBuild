# AIBuild — ИИ-строитель для Minecraft (Paper/Purpur 26.3)

Плагин генерирует с нуля и редактирует постройки с помощью **DeepSeek V4.1 Flash**
(`deepseek/deepseek-v4.1-flash`) через подписку **Command Code**. Каждая постройка проходит
проектирование цельной программы, локальную компиляцию геометрии и **самопроверку ИИ**
(цельное ревью в standard, три специалиста в extra, объективный анализатор).
После этого постройка ставится в мир с полной историей версий.
[Подробности и реальные замеры](../docs/generation-performance.md).

Версия 1.1.0 добавляет пространственный отчёт для текстовой модели, отдельные критерии качества
и явные черновики. Неодобренная правка сохраняется отдельно и не заменяет прежнюю версию.
[Изменения проверки качества и ограничения](../docs/text-quality.md).

В 1.2.0 проверка отличает габариты объектов от размеров стен здания, объясняет причины
отказа в чате и сокращает контекст промежуточных проверок. Итоговое ревью всей модели обязательно.
[Поведение и результаты проверки](../docs/focused-review.md).

## 3.0: постройки уровня сильных билдеров

В 3.0 качество закладывается в инструменты, а не только в модель:
- **Наборы приёмов билдеров** (библиотека 3.0):
  - `volume()` — корпус здания с цоколем, каркасом, заглублённым заполнением (три слоя глубины), окнами
    с подоконниками, ставнями и ящиками цветов, дверью со ступенькой и фонарём, этажами и слоистой крышей;
  - `tower()` и `curtainWall()` — башни и крепостные стены;
  - крыши со свесом, нижней кромкой, торцевой обвязкой и коньком, мансарды и слуховые окна;
  - деревья с корнями, ветками из древесины и смешанной листвой;
  - смешанный грунт `groundCover()`, рельеф `terrain()`, пруды, камни;
  - **затенение** скульптур `shade()` и `ramp()` по настоящим цветам блоков, палитры `palette()`.
- **Рецепты** для 10 типов построек (дом, замок, башня, храм, статуя, существо, корабль, природа, сцена, мост)
  подбираются по запросу без вызова модели.
- **Новые «глаза»:** рендер трассировкой лучей с настоящими текстурами граней, формой ступенек, плит, заборов
  и растений, тенями и затенением углов. На листе 4 изометрии, вид с высоты глаз игрока и план сверху,
  плюс крупные планы частей.
- **Арт-директор и скульпторы:** после выбора лучшего варианта арт-директор смотрит на рендер и выбирает
  до 3 частей (extra — 5). Скульпторы параллельно переписывают по одной части, глядя на её крупный план.
  Доработка остаётся, только если она выполняется, не добавляет дефектов и судья не предпочёл прежний вид.
- Стандартный режим думает больше (`build: medium`, 120k токенов), размер до 160 блоков от центра.

Старые постройки продолжают работать с библиотекой 2.0, с которой были созданы. Сравнить версии:
`/aib bench create <запрос>` (2.0 против 3.0) или `/aib bench suite` (16 запросов подряд), затем слепое
голосование `tools/blind_ballot.py`. Подробности — в [docs/craft-v3.md](../docs/craft-v3.md).

## 2.0: ИИ пишет программу постройки

С версии 2.0 (`generation.create-strategy: script`, по умолчанию) ИИ пишет не список JSON-операций, а одну
**программу на JavaScript**. Программа выполняется в песочнице. В ней доступны:
- циклы, математика, функции и симметрия;
- гладкие фигуры: трубы по кривым, лофт, вращение профиля, плавное слияние, повороты на любой угол;
- автоматическое сглаживание склонов ступеньками и полублоками;
- градиенты материалов, «выветривание» (мох, трещины) и пятна шума;
- наборы для архитектуры, интерьера и природы: крыши-купола и луковицы, арки, окна, двери, деревья, скалы, холмы, тропинки.

Как проходит генерация:
1. Модель пишет несколько вариантов параллельно (standard 2, extra 3).
2. Ошибки программы возвращаются ей как трассировка.
3. Лучший вариант выбирается по анализатору, затем по сравнению картинок.
4. Раунды критика смотрят на рендер, анализ и код и правят **код** программы.

Правка принимается, только если не добавляет дефектов анализатора и судья не предпочёл прежнюю версию.
Самооценка ≥ 86 больше не нужна для одобрения. `/aib edit` меняет программу сохранённой версии.

Цвета рендера берутся из текстур клиента Minecraft (`render.textures`). Клиент скачивается один раз с серверов
Mojang, хранится только таблица цветов. Подробности, проверки и ограничения — в
[docs/build-scripts.md](../docs/build-scripts.md).

Сравнение со старым конвейером: `/aib bench create [--mode m] <промпт>` строит обоими способами без размещения
в мире. Слепое голосование: `python3 tools/blind_ballot.py make …`, затем `tally` (набор промптов —
`tools/bench_suite.txt`). Вернуть поведение 1.x: `generation.create-strategy: compiled`.

## Команды

| Команда | Что делает |
|---|---|
| `/aib create [--mode fast\|light\|standard\|extra] <описание>` | новая детальная постройка перед игроком (любой язык, размеры вида «10 на 10» соблюдаются) |
| `/aib mode [режим]` | выбрать свой режим думания ИИ (сохраняется); без аргумента — список режимов |
| `/aib edit <запрос>` | изменить активную постройку в любой момент («крышу из тёмного дуба», «добавь второй этаж») |
| `/aib chat` | режим диалога: каждое сообщение в чат — запрос к ИИ для активной постройки; «выход» — выключить |
| `/aib undo` / `/aib redo` | переключение версий (мир обновляется диффом, исходный ландшафт хранится) |
| `/aib list`, `/aib select [id\|look]`, `/aib info`, `/aib tp` | управление постройками |
| `/aib render` | изометрический PNG (4 ракурса) в `plugins/AIBuild/renders/` |
| `/aib fix [id]` | автоисправление ориентации ступенек и полублоков без ИИ (новая версия, `/aib undo` вернёт) |
| `/aib wand`, `/aib pos1`, `/aib pos2`, `/aib import <имя>` | взять существующую (ручную) постройку под ИИ-редактирование |
| `/aib watch [id]` | (владелец, админ) одноразовая ссылка на живой просмотр постройки в браузере; без `id` — активная постройка |
| `/aib remove`, `/aib cancel`, `/aib status`, `/aib reload` | удалить (с восстановлением ландшафта), отменить задачу, статус, перезагрузка конфига |
| `/aib bench create [--mode m] [--a вариант] [--b вариант] <описание>` | (админ) два варианта конвейера на одном запросе, рендеры для слепого сравнения. По умолчанию `script-v3.3` против `studio`; ещё есть `script-v2`, `script-v3`, `script-v3.1`, `script-v3.2`, `compiled` |

Из консоли: `/aib create --at <мир> <x> <y|~> <z> <north|east|south|west> <описание>` — `(x,z)` — точка перед
фасадом, направление — куда «смотрит» зритель (постройка встанет в этом направлении фасадом к точке).

Права: `aibuild.use` (по умолчанию op), `aibuild.admin`.

## Как это работает

```
запрос ─► ПРОГРАММА: бриф + все операции одним вызовом, с думанием выбранного режима
       ─► КОМПИЛЯТОР: building/repeat/roof/trim → блоки → автоисправление форм → живое превью
       ─► САМОПРОВЕРКА: анализатор (висящие блоки, опоры факелов/лестниц, тёмные места,
            дыры в крыше, заблокированные двери, доступ на этажи, размеры корпуса, однообразные фасады)
            + цельный ревьюер standard / 3 параллельных специалиста extra → исправления,
            проверка точных условий исправлений локально, конфликтующие правки перепроверяются
       ─► РАЗМЕЩЕНИЕ: дифф по тикам, без физики, хрупкие блоки последними, фундамент до грунта,
            исходный ландшафт сохраняется для undo/remove
```

`generation.create-strategy: staged` возвращает прежний путь: отдельный план и 4–6 этапов.
Прогресс показывается в боссбаре и чате; консольные задачи видят операторы сервера.

Правки (`/aib edit`, чат) работают от текущей версии по схеме `generation.edit-strategy`:

| `edit-strategy` | Как | Когда лучше |
|---|---|---|
| `plan` (по умолчанию) | план изменения (область, шаги, критерии приёмки, что нельзя трогать) -> **одним вызовом** строится всё изменение по плану -> проверка по критериям | обычно: план задаёт рамки, но постройка делается цельно |
| `steps` | план -> каждый шаг отдельным вызовом (видит актуальную модель) -> проверка | очень большие правки (новая пристройка с интерьером) |
| `direct` | один вызов строит изменение (старое поведение) | мелкие правки, экономия вызовов |

Для совсем другой постройки ИИ сам выбирает перестройку с нуля. Каждая правка — новая версия, `/aib undo` откатывает.

**Самопроверка** (`generation.review-strategy: adaptive`): из брифа (или критериев правки) строится чек-лист;
эксперты (конструктив / экстерьер / интерьер, для правок — ревьюер изменения) отмечают пункты как проверенные
или найденные-и-исправленные и **сами решают, когда проверка завершена**: эксперт заканчивает, когда все его
пункты подтверждены и серьёзных проблем не осталось (мелкая полировка не продлевает); исправил серьёзное —
перепроверка в следующем раунде; если все закончили, а пункты не проверены (или есть критические находки
анализатора), нужный эксперт возвращается. Каждый эксперт работает только в своей зоне. Предел —
`adaptive-max-rounds`. Старая схема — `review-strategy: fixed`.

`/aib bench review [--mode m] <промпт>` и `/aib bench edit <id> [--mode m] <правка>` (админ) сравнивают схемы
на одинаковых входных данных (в мир ничего не ставится): одна общая постройка, затем варианты параллельно и
слепой судья; отчёт — `plugins/AIBuild/bench/<id>/report.md`, сводка — `python3 tools/bench_summary.py`.

## Режимы думания

| Режим | `--mode` | Думание: строительство / ревью / повторное ревью | Ревьюеры |
|---|---|---|---|
| Без думания | `fast` | off / off / off | 3 специалиста |
| Лёгкое думание | `light` | low / off / off | 3 специалиста |
| Стандарт (по умолчанию) | `standard` | low / low / low | 1 цельный ревьюер |
| Экстра-думание | `extra` | high / high / low | 3 специалиста |

Замер небольшого дома на новом конвейере: standard **3 мин 32 с**, extra **7 мин 56 с**.
Это отдельные замеры, не гарантированное время. Лимит адаптивного ревью — `adaptive-max-rounds`;
при `review-strategy: fixed` действует `verify-rounds` выбранного режима.

Замеры одного вызова на реальных промптах: `off` ≈ 10 с, `low` ≈ 3,5 мин (~35k токенов мыслей),
`medium`/`high` ≈ 5–7 мин (~50–60k). Без думания модель быстрее в 20 раз, но чаще ошибается и иногда
зацикливается — от этого защищают ограничение области постройки (операции вне плота отклоняются) и
отбраковка ответов проверки, переписывающих > 35 % постройки. Если вызов тратит весь бюджет на размышления,
он автоматически повторяется с уровнем ниже. Пресеты настраиваются в `config.yml` → `modes`.

Разово: `/aib create --mode extra <описание>`, `/aib edit --mode fast <запрос>`; режим по умолчанию сервера —
`generation.default-mode`. Режим, которым сделана каждая версия, виден в `/aib info`.

## Настройка (`plugins/AIBuild/config.yml`)

* `api.key` — ключ Command Code `user_…` (или переменная `COMMANDCODE_API_KEY`).
* `api.transport: auto` — Provider API (`/provider/v1/chat/completions`, планы Pro/GOAT); для ключа плана
  Go автоматически переключается на `/alpha/generate`.
* `modes.<режим>` — уровни думания `off|low|medium|high|xhigh|max` для plan/build/review/review-followup/edit,
  `verify-rounds`, `max-tokens` (до 200000); `generation.default-mode` — режим по умолчанию.
* `generation.min-score` (86), `live-preview` (true), `auto-orient` (true).
* `generation.live-view.*` — одноразовые ссылки на живой просмотр, шесть ключей в таблице ниже.
* `placement.blocks-per-tick`, `foundation-block`, `max-foundation-depth`.
* `debug.save-transcripts` — полные диалоги с ИИ в `plugins/AIBuild/logs/<id>/…`.

Большие постройки (> 34 блоков по стороне) передаются модели в компактном виде — по строкам с явными
диапазонами координат (`z=12: 0-49 AA, 50 Bv`), а не сеткой символов: для замка 50×50 это ~90k символов вместо
~420k.

## Живой просмотр

Каждая задача получает ссылку `/live/<токен>/`, по которой в браузере видно, как растёт постройка, что ИИ
печатает и на каком этапе конвейера он находится. Тихие задачи (`/aib bench` и его подзадачи) ссылки не
получают. Страница и поток событий отдаёт встроенный HTTP-сервер
плагина (`dev.aibuild.live`, JDK `HttpServer` + SSE); внешних запросов страница не делает.

Кнопка `Debug` (клавиша `d`) показывает разбор задачи: каждый вызов модели с промптом, рассуждениями и
сырым ответом, каждый запуск программы постройки с текстом и ошибкой песочницы, каждую партию операций с
числом упавших, плюс этапы конвейера между ними. Раскрытие строки подгружает подробности
(`/live/<токен>/step/<n>`), `failures` оставляет только упавшие шаги, `save` выгружает весь разбор в markdown.
Разбор живёт в памяти сессии и исчезает вместе со ссылкой.

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `generation.live-view.enabled` | `true` | Включает сервер и выдачу ссылок. `false` — задач со ссылкой нет, `/aib watch` отвечает «Живой просмотр выключен в конфиге». |
| `generation.live-view.bind` | `"127.0.0.1"` | Интерфейс, который слушает сервер. Loopback: наружу сам не открывается. `0.0.0.0` откроет порт всем, кто до него дотянется, — лучше туннель или reverse proxy. |
| `generation.live-view.port` | `0` | TCP-порт; `0` — первый свободный. Поставьте фиксированный, если на него смотрит туннель или proxy. Фактический порт пишется в лог при старте. |
| `generation.live-view.public-url` | `""` | Адрес, который видит игрок, например `https://builds.example.com`. Пусто — в чат по ходу задачи ссылка не приходит (она пишется в лог), а `/aib watch` показывает loopback-адрес с предупреждением. |
| `generation.live-view.max-viewers` | `8` | Сколько браузеров одновременно могут держать поток `/events` (1–64). Каждый поток занимает поток сервера; лишним отдаётся 503. |
| `generation.live-view.expire-minutes` | `15` | Сколько минут ссылка живёт после конца задачи (1–1440). Дальше токен удаляется, `/live/<токен>/` отдаёт 404. |

`/aib watch [id]` (синонимы `/aib live`, `/aib смотреть`) показывает ссылку владельцу постройки и
`aibuild.admin`. Ссылка одна на запуск: новый запуск той же постройки выдаёт новую и гасит прежнюю.

Порядок включения наружу: фиксированный `port` → туннель или reverse proxy на `127.0.0.1:<port>` →
`public-url` с внешним адресом. Проверка: `curl -s http://127.0.0.1:<port>/healthz` отвечает `ok`.
Для SSE на proxy нужно `proxy_buffering off`.

Почему по умолчанию только loopback: URL — единственная защита страницы, учётных записей на ней нет.
Пока `public-url` пуст, ссылка с другой машины не откроется: `/aib watch` печатает loopback-адрес и
предупреждает об этом, а в чат по ходу задачи ссылка не приходит — она только пишется в лог
(`Live view for build <id> at /live/<token>/`, уровень INFO, с полным токеном). Так площадка не уходит в
сеть без решения оператора.

Изменения в `generation.live-view` применяются только после перезапуска сервера: `/aib reload` перечитывает
остальной конфиг, но слушатель не перезапускает. Устройство, эндпоинты и формат кадра —
[docs/live-view.md](../docs/live-view.md).

