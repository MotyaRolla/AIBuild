# AIBuild — ИИ-строитель для Minecraft (Paper/Purpur 26.3)

Плагин генерирует с нуля и редактирует постройки с помощью **DeepSeek V4.1 Flash**
(`deepseek/deepseek-v4.1-flash`) через подписку **Command Code**. Каждая постройка проходит
проектирование цельной программы, локальную компиляцию геометрии и **самопроверку ИИ**
(цельное ревью в standard, три специалиста в extra, объективный анализатор).
После этого постройка ставится в мир с полной историей версий.
[Подробности и реальные замеры](../docs/generation-performance.md).

Версия 1.1.0 добавляет пространственный отчёт для текстовой модели, отдельные критерии качества
и явные черновики. Неодобренная правка сохраняется отдельно и не заменяет прежнюю версию.
[Изменения проверки качества и ограничения](../docs/text-quality.md).

## Команды

| Команда | Что делает |
|---|---|
| `/aib create [--mode fast\|light\|standard\|extra] <описание>` | новая детальная постройка перед игроком (любой язык, размеры вида «10 на 10» соблюдаются) |
| `/aib mode [режим]` | выбрать свой режим думания ИИ (сохраняется); без аргумента — список режимов |
| `/aib edit <запрос>` | изменить активную постройку в любой момент («крышу из тёмного дуба», «добавь второй этаж») |
| `/aib chat` | режим диалога: каждое сообщение в чат — запрос к ИИ для активной постройки; «выход» — выключить |
| `/aib undo` / `/aib redo` | переключение версий (мир обновляется диффом, исходный ландшафт хранится) |
| `/aib list`, `/aib select [id\|look]`, `/aib info`, `/aib tp` | управление постройками |
| `/aib render` | изометрический PNG (4 ракурса) в `plugins/AIBuild/renders/` |
| `/aib fix [id]` | автоисправление ориентации ступенек и полублоков без ИИ (новая версия, `/aib undo` вернёт) |
| `/aib wand`, `/aib pos1`, `/aib pos2`, `/aib import <имя>` | взять существующую (ручную) постройку под ИИ-редактирование |
| `/aib remove`, `/aib cancel`, `/aib status`, `/aib reload` | удалить (с восстановлением ландшафта), отменить задачу, статус, перезагрузка конфига |

Из консоли: `/aib create --at <мир> <x> <y|~> <z> <north|east|south|west> <описание>` — `(x,z)` — точка перед
фасадом, направление — куда «смотрит» зритель (постройка встанет в этом направлении фасадом к точке).

Права: `aibuild.use` (по умолчанию op), `aibuild.admin`.

## Как это работает

```
запрос ─► ПРОГРАММА: бриф + все операции одним вызовом, с думанием выбранного режима
       ─► КОМПИЛЯТОР: building/repeat/roof/trim → блоки → автоисправление форм → живое превью
       ─► САМОПРОВЕРКА: анализатор (висящие блоки, опоры факелов/лестниц, тёмные места,
            дыры в крыше, заблокированные двери, доступ на этажи, размеры корпуса, однообразные фасады)
            + цельный ревьюер standard / 3 параллельных специалиста extra → исправления,
            проверка точных условий исправлений локально, конфликтующие правки перепроверяются
       ─► РАЗМЕЩЕНИЕ: дифф по тикам, без физики, хрупкие блоки последними, фундамент до грунта,
            исходный ландшафт сохраняется для undo/remove
```

`generation.create-strategy: staged` возвращает прежний путь: отдельный план и 4–6 этапов.
Прогресс показывается в боссбаре и чате; консольные задачи видят операторы сервера.

Правки (`/aib edit`, чат) работают от текущей версии по схеме `generation.edit-strategy`:

| `edit-strategy` | Как | Когда лучше |
|---|---|---|
| `plan` (по умолчанию) | план изменения (область, шаги, критерии приёмки, что нельзя трогать) -> **одним вызовом** строится всё изменение по плану -> проверка по критериям | обычно: план задаёт рамки, но постройка делается цельно |
| `steps` | план -> каждый шаг отдельным вызовом (видит актуальную модель) -> проверка | очень большие правки (новая пристройка с интерьером) |
| `direct` | один вызов строит изменение (старое поведение) | мелкие правки, экономия вызовов |

Для совсем другой постройки ИИ сам выбирает перестройку с нуля. Каждая правка — новая версия, `/aib undo` откатывает.

**Самопроверка** (`generation.review-strategy: adaptive`): из брифа (или критериев правки) строится чек-лист;
эксперты (конструктив / экстерьер / интерьер, для правок — ревьюер изменения) отмечают пункты как проверенные
или найденные-и-исправленные и **сами решают, когда проверка завершена**: эксперт заканчивает, когда все его
пункты подтверждены и серьёзных проблем не осталось (мелкая полировка не продлевает); исправил серьёзное —
перепроверка в следующем раунде; если все закончили, а пункты не проверены (или есть критические находки
анализатора), нужный эксперт возвращается. Каждый эксперт работает только в своей зоне. Предел —
`adaptive-max-rounds`. Старая схема — `review-strategy: fixed`.

`/aib bench review [--mode m] <промпт>` и `/aib bench edit <id> [--mode m] <правка>` (админ) сравнивают схемы
на одинаковых входных данных (в мир ничего не ставится): одна общая постройка, затем варианты параллельно и
слепой судья; отчёт — `plugins/AIBuild/bench/<id>/report.md`, сводка — `python3 tools/bench_summary.py`.

## Режимы думания

| Режим | `--mode` | Думание: строительство / ревью / повторное ревью | Ревьюеры |
|---|---|---|---|
| Без думания | `fast` | off / off / off | 3 специалиста |
| Лёгкое думание | `light` | low / off / off | 3 специалиста |
| Стандарт (по умолчанию) | `standard` | low / low / low | 1 цельный ревьюер |
| Экстра-думание | `extra` | high / high / low | 3 специалиста |

Замер небольшого дома на новом конвейере: standard **3 мин 32 с**, extra **7 мин 56 с**.
Это отдельные замеры, не гарантированное время. Лимит адаптивного ревью — `adaptive-max-rounds`;
при `review-strategy: fixed` действует `verify-rounds` выбранного режима.

Замеры одного вызова на реальных промптах: `off` ≈ 10 с, `low` ≈ 3,5 мин (~35k токенов мыслей),
`medium`/`high` ≈ 5–7 мин (~50–60k). Без думания модель быстрее в 20 раз, но чаще ошибается и иногда
зацикливается — от этого защищают ограничение области постройки (операции вне плота отклоняются) и
отбраковка ответов проверки, переписывающих > 35 % постройки. Если вызов тратит весь бюджет на размышления,
он автоматически повторяется с уровнем ниже. Пресеты настраиваются в `config.yml` → `modes`.

Разово: `/aib create --mode extra <описание>`, `/aib edit --mode fast <запрос>`; режим по умолчанию сервера —
`generation.default-mode`. Режим, которым сделана каждая версия, виден в `/aib info`.

## Настройка (`plugins/AIBuild/config.yml`)

* `api.key` — ключ Command Code `user_…` (или переменная `COMMANDCODE_API_KEY`).
* `api.transport: auto` — Provider API (`/provider/v1/chat/completions`, планы Pro/GOAT); для ключа плана
  Go автоматически переключается на `/alpha/generate`.
* `modes.<режим>` — уровни думания `off|low|medium|high|xhigh|max` для plan/build/review/review-followup/edit,
  `verify-rounds`, `max-tokens` (до 200000); `generation.default-mode` — режим по умолчанию.
* `generation.min-score` (86), `live-preview` (true), `auto-orient` (true).
* `placement.blocks-per-tick`, `foundation-block`, `max-foundation-depth`.
* `debug.save-transcripts` — полные диалоги с ИИ в `plugins/AIBuild/logs/<id>/…`.

Большие постройки (> 34 блоков по стороне) передаются модели в компактном виде — по строкам с явными
диапазонами координат (`z=12: 0-49 AA, 50 Bv`), а не сеткой символов: для замка 50×50 это ~90k символов вместо
~420k.

## Сборка

```
mvn -Dmaven.test.skip=true package     # target/AIBuild.jar (Java 25, paper-api 26.3)
```
Самопроверочные тесты модулей — `src/test/java/**/…Check.java`, `LlmUnitTests` (запуск через `java -cp`).
