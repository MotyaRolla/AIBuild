# AIBuild 3D — идея

**Проблема прежней архитектуры.** ИИ писал команды `fill/walls/roof` прямо в воксельную сетку Minecraft и «видел»
свою постройку только по ASCII-схеме слоёв. Он не мог оценить форму, силуэт, пропорции — только координаты.
Отсюда типичные дефекты: висящие блоки, дыры в крыше, плоские фасады, «просто коробка».

**Новая идея.** Строительство идёт в два этапа, и между ними — настоящая 3D-сцена:

1. **Модель строится в three.js.** ИИ работает не с блоками, а со сценой: стены, проёмы, крыши, профили,
   балясины, карнизы, черепица, окна — параметрические объекты с реальной геометрией. Каждая итерация:
   правка сцены → **рендер нескольких ракурсов** → критика (ИИ-критик + объективные проверки геометрии) → правка.
   Десятки попыток на одну постройку вместо одного прохода.
2. **Готовая модель переносится в Minecraft.** Вокселизация сцены: рейкаст по сетке 1×1×1, выбор блока по
   материалу и нормали поверхности, автоподбор состояний (ступеньки/полублоки/заборы/стёкла), ориентация по
   геометрии, устранение висящих блоков. Результат — `.litematic`/схема или прямая установка плагином.

**Почему это лучше.**
* У ИИ появляется «зрение»: он видит рендеры, как архитектор, а не таблицу координат.
* Геометрия проверяема математически: нет дыр, замкнутый объём, ничего не висит, соблюдены размеры.
* Детализация достигается итерациями, а не одним гигантским ответом (лимит токенов больше не узкое место).
* Перенос в Minecraft — детерминированный код, а не творчество модели: он не может «забыть» блок.

## Слои

```
packages/core      модель сцены (только данные), DSL операций, рендер-сервис, перенос в Minecraft, проверки
packages/studio    веб-студия: three.js просмотр, галерея ракурсов, история итераций
packages/transfer  формат .litematic + установка на сервер (Paper) через существующий плагин
agents/            оркестратор «много попыток»: генератор → рендер → критик → правка
```

## Формат модели (`StructureSpec`)

Сцена описывается **декларативно** (JSON), а не кодом three.js — так ИИ может её править, а сервер собирать
меши. Любой примитив имеет материал и слой (структура / декор / интерьер).

```jsonc
{
  "name": "medieval house", "seed": 1234,
  "palette": { "wall": "#d8cdb8", "frame": "#3b2a1c", "roof": "#6b4a2f" },
  "objects": [
    {"id": "body", "type": "box", "from": [0,0,0], "to": [9,6,9], "material": "wall", "hollow": true,
     "openings": [{"wall": "south", "x": 4, "y": 1, "w": 2, "h": 3, "kind": "door"}]},
    {"type": "prism", "from": [0,7,0], "to": [9,7,9], "style": "gable", "ridge": "x", "material": "roof", "overhang": 1},
    {"type": "cylinder", "center": [0,0,0], "radius": 2, "height": 12, "material": "stone", "hollow": true},
    {"type": "ring", "center": [0,0,0], "radius": 3, "y": 7, "material": "trim", "profile": "cornice"},
    {"type": "window", "wall": "south", "at": [2,3], "w": 1, "h": 2, "frame": "frame", "glass": "glass"},
    {"type": "stairs", "from": [0,0,0], "to": [1,5,4], "axis": "z", "material": "wood"}
  ]
}
```

## Конвейер «много попыток»

```
промпт → план (стиль, размеры, палитра, список объектов)
       → сборка сцены (итерация 1)
       → рендер 4 ракурса + 2 разреза + аксонометрия
       → проверки: размеры, замкнутость, опоры, проходимость, тёмные зоны
       → критик ИИ: «что плохо на этих картинках» → список правок
       → правка сцены (итерации 2..N, до порога качества)
       → вокселизация → перенос в Minecraft → проверка уже на блоках
```

Порог остановки: критик не находит серьёзных замечаний И объективные проверки чисты И качество не растёт
две итерации подряд. Каждая итерация сохраняется (история + рендеры), поэтому откат — это выбор версии.

## Перенос в Minecraft

1. Сетка заполняется рейкастом по треугольникам сцены (BVH-ускорение, детерминированный порядок).
2. Ячейка получает блок материала; если поверхность наклонная — ступенька с поворотом по нормали;
   если плоская сверху и снизу — полублок; столбики — забор; стеклянные плоскости — панель.
3. Постобработка: убрать висящие, добавить опоры, сориентировать по соседям, посчитать статистику.
4. Экспорт: `.litematic` (готовая схема) и/или команды для плагина.

## Что считается успехом эксперимента

* Сцена собирается и рендерится без ошибок; ИИ делает ≥ 8 итераций на постройку.
* Перенос даёт в Minecraft постройку без висящих блоков и с замкнутой оболочкой (проверяется анализатором).
* Слепое сравнение: постройка через three.js лучше, чем прежняя (блочная) — судья, как в `/aib bench`.
