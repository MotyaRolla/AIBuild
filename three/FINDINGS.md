# Проверки окружения (эксперимент three.js)

## 1. Модель видит картинки — ДА

`deepseek/deepseek-v4.1-flash` через Command Code принимает изображения в формате OpenAI-совместимых
content-parts (`{type:'image_url', image_url:{url:'data:image/png;base64,...'}}`).

Проверка на контрольной картинке (96×96, три красных круга по диагонали, зелёный квадрат справа сверху,
светло-серый фон) — ответ модели:

```json
{"red_circles":3,"green_squares":1,"background":"light gray"}
```

Всё верно, то есть это не угадывание по тексту промпта, а реальное зрение. Значит основной замысел
(ИИ строит сцену → смотрит на рендеры → критикует и правит) реализуем полностью.

Замечания:
* первая попытка отправить битый PNG дала `HTTP 400 InvalidParameter: invalid base64 image_url` — то есть
  нужен корректный PNG (наш энкодер должен выдавать валидный файл, это проверяется тестами рендера);
* `reasoning_effort: off` для vision работает, но для оценки картинок разумнее `low`/`medium`;
* картинки учитываются в prompt_tokens, поэтому ракурсы стоит отдавать в разумном размере (400–640 px).

## 2. three.js в node

`three@0.187.0` установлен (`three/node_modules/three`). В node он используется только для расчётов,
WebGL-рендера нет — поэтому картинки рисует собственный софтверный растеризатор (задача B).

## 3. Рендер без браузера

Headless-браузера и GPU нет, поэтому:
* PNG пишем сами (node:zlib + CRC32);
* растеризация — свой z-buffer по треугольникам сцены, с солнцем и мягким AO/контуром.
